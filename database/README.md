# MedFlowAI Database

- **Version**: v4.1 Priority 1
- **Engine**: PostgreSQL 16+ (designed for 12+)
- **Schema**: `public` (no schema prefix on tables)
- **PK type**: `bigint GENERATED BY DEFAULT AS IDENTITY`
- **Tables**: 44 (357 columns, 93 FKs)
- **Source of truth**: `database/medflow_schema_v4_1.sql`

## Layout

```
database/
├── medflow_schema_v4_1.sql       # Current source of truth (DDL only)
├── migrations/
│   ├── 001_create_refresh_tokens.sql              # legacy v1.2 migration (do not re-apply)
│   ├── 002_v41_priority1_schema.sql               # v4.1 schema (verbatim from upstream)
│   ├── 003_v41_priority1_seed.sql                 # v4.1 demo seed (PBKDF2-rehashed)
│   ├── 004_readd_auth_verification_challenges.sql # OTP table dropped in v4.1 — re-added for AuthOtpService
│   └── 005_readd_auth_session_and_audit_cols.sql  # auth_sessions + audit_logs.ip_address re-added
└── README.md
```

## Apply from scratch

```bash
# Against a fresh empty database "medflow_db" — apply schema, seed, then deltas
psql -h localhost -U postgres -d medflow_db -v ON_ERROR_STOP=1 -f database/migrations/002_v41_priority1_schema.sql
psql -h localhost -U postgres -d medflow_db -v ON_ERROR_STOP=1 -f database/migrations/003_v41_priority1_seed.sql
psql -h localhost -U postgres -d medflow_db -v ON_ERROR_STOP=1 -f database/migrations/004_readd_auth_verification_challenges.sql
psql -h localhost -U postgres -d medflow_db -v ON_ERROR_STOP=1 -f database/migrations/005_readd_auth_session_and_audit_cols.sql
```

For the Docker dev container (`medflow-postgres` on port 5433):

```bash
docker cp database/migrations/002_v41_priority1_schema.sql medflow-postgres:/tmp/schema.sql
docker cp database/migrations/003_v41_priority1_seed.sql medflow-postgres:/tmp/seed.sql
docker exec medflow-postgres psql -U postgres -d medflow_db -v ON_ERROR_STOP=1 -f /tmp/schema.sql
docker exec medflow-postgres psql -U postgres -d medflow_db -v ON_ERROR_STOP=1 -f /tmp/seed.sql
```

## Known gaps vs legacy v1.2

- **Dropped from schema**: 11 legacy tables removed (e.g., `appointment_events`, `dispenses` → `medication_dispenses`, `queues`/`queue_events`/`queue_policies` → `queue_*` consolidation, `patient_allergies`, `patient_medical_history_entries`, `visit_vitals`, `payment_allocations`, `payment_gateway_events`, `payment_qr_sessions`, `outbox_events`, `scan_events`, `scannable_codes`, `identity_verifications`, `auth_verification_challenges`, `integration_configs` → `system_integrations`, `service_points` → `queue_service_points`, `refresh_tokens` → `auth_sessions`, `medical_record_amendments` → `clinical_addenda`, `medicine_prices` → `service_prices`, `diagnostic_result_files` → `diagnostic_result_versions.report_file_url`, `dispense_batch_allocations` → `dispense_items.medicine_batch_id`, `appointment_policies`/`visit_assignment_history`, `rooms` → `hospital_rooms`, `examination_schedules` → `examination_slots`).
- **Trigger guards removed**: legacy schema had 15 plpgsql guard functions + 19 triggers enforcing cross-hospital consistency, immutability of finalized records, queue numbering, etc. The v4.1 file ships none — these must be re-implemented if still required.
- **ID type changed**: `uuid` → `bigint identity`. Backend entities/configuration require refactor.
- **Schema moved**: `medflow.*` → `public.*`.
- **Password hashing**: seed file has been rehashed to **PBKDF2-SHA256** (ASP.NET Identity `PasswordHasher<User>`). Demo logins (`Demo@12345`) work as soon as the backend is pointed at this DB.

## Conventions

- Migration files: `NNN_description.sql` in `migrations/` — never edit a committed file.
- Always wrap migrations in `BEGIN; … COMMIT;` and use `IF NOT EXISTS` guards where applicable.
- New columns/tables → new migration, plus update this README and `medflow_schema_v4_1.sql`.
